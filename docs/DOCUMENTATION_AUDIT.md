# Аудит документации — 2026-09-13

Проверена локальная копия `karateka-git/obsChatBot`, исходный commit `a6ee0f0`.
Документация сопоставлена с конфигурацией, Compose, CLI, реестром команд,
incoming flow, схемой SQLite, поиском, GitHub connector и существующими тестами.
Это аудит описаний и воспроизводимости инструкций, а не полный аудит безопасности
или проверка production-сервера. Реальные Telegram/VK, GitHub write-back и платные
AI API не вызывались; внешние инструкции провайдеров отдельно не валидировались.

## Оценка

Архитектура и сложные сценарии описаны подробно: изоляция пользователей,
синхронизация, правила vault, FTS fallback, embedding checkpoints и подтверждение
write-back имеют соответствующие реализации и тесты. Основные пробелы были в
первом запуске, границах диагностических команд и различении текущего состояния
с историческими планами. Эксплуатационная документация пока недостаточна для
воспроизведения сервера и проверенного восстановления из backup с нуля.

## Следующие улучшения кода и эксплуатации

Эти изменения не внесены в runtime в рамках проверки документации.

1. **Разделить конфигурацию и healthcheck по каналам.**
   `data/config.py` требует Telegram token для VK, а `run_healthcheck` в
   `presentation/cli/main.py` проверяет Telegram и не проверяет VK credentials.
   Нужны проверки выбранного адаптера и отдельная проверка фактической готовности.
2. **Убрать скрытую подмену ключа LLM в Compose.**
   Текущий `OPENAI_API_KEY: ${EMBEDDING_API_KEY}` мешает разным провайдерам
   и отключению semantic search. Лучше явно передавать независимые ключи,
   сохранив возможность пользователю задать одинаковые значения.
3. **Сделать CLI обработки URL явным по пользователю.**
   `run_process_url_command` использует default `app_user_id=1`, а миграция
   пользователя не создаёт. Нужен явный аргумент и понятная проверка существования
   пользователя до записи. Нынешний CLI-тест с fake use case эту интеграцию
   не проверяет; полезен сценарий с реальной временной БД.
4. **Останавливать PowerShell-проверки при ошибке Docker.**
   В `scripts/check-all.ps1` одного `$ErrorActionPreference = "Stop"` недостаточно
   для native exit codes в Windows PowerShell. Проверять `$LASTEXITCODE` после
   каждого шага, возвращать ненулевой код. Отдельно запускать полный unittest-набор.
5. **Оформить воспроизводимое развёртывание и восстановление.**
   В Git отсутствуют описанные systemd units и backup script. Нужны шаблоны без
   секретов, порядок установки, восстановления SQLite при остановленных workers,
   проверки целостности и отката релиза. Зафиксировать результат учебного
   восстановления, дату последней проверки VPS и SHA развёрнутого кода.
6. **Закрепить production-миграции.**
   `migration_runner.py` не сверяет содержимое применённого SQL. При сохранении
   реальных данных новые версии схемы должны идти отдельными миграциями;
   полезно обнаруживать изменение уже применённой миграции по checksum.
7. **Сократить повторение изменяемых сведений.**
   Onboarding повторяется в RUN, OPERATIONS и GITHUB_APP; состояние VPS —
   в README, ARCHITECTURE, ROADMAP и PRODUCTION. Оставлять подробности в одном
   профильном документе, из остальных ссылаться. Историю этапов стоит постепенно
   отделить от короткого текущего плана. Добавить в CI проверку локальных ссылок
   и документированных CLI-команд.

`python -m unittest discover -s tests`: **364 теста, OK**.
Режимы `--sqlite-smoke`, `--pipeline-smoke`, `--analysis-smoke` прошли.
Проверены локальные Markdown-ссылки на файлы: отсутствующих целей нет.
Минимальный YAML из инструкции принят реальным parser. На временной пустой БД
воспроизведён отказ `--process-url`: `FOREIGN KEY constraint failed`, exit code 1.
`git diff --check` не обнаружил ошибок whitespace.
Они используют временные базы; production-данные не затрагивались.
Docker-образ и работа с реальными credentials в этом аудите не проверялись.
